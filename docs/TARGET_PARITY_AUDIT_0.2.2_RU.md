# Аудит Team Tracker GTNH 0.2.2 против GT Community Pack Modern

Дата проверки: 2026-10-05  
Целевая среда: GTNH 2.9.0-beta-3, Minecraft 1.7.10  
Проверяемый JAR: `teamtrackergtnh-0.2.2.jar`  
SHA-256: `04cc5b866e1a526fd6831dfd410ac67186e914122484d63833d772bdf489bcb4`

## Итог

Основной сценарий реализован правильно: сервер отправляет координаты всех онлайн-участников той же команды ServerUtilities без ограничения по расстоянию, а клиент показывает их головы на миникарте, большой карте и в POV. По статическому анализу и сборочным проверкам мод должен работать как функциональная beta.

Однако версия 0.2.2 пока не является визуальной и поведенческой копией 1:1 современного Xaero Tracked Players. До релиза с формулировкой «как в GCP Modern» нужны минимум исправление квадратной миникарты и приведение большой карты/POV к правилам целевого рендера. Обязателен мультиплеерный прогон двумя клиентами.

Оценка состояния:

- основной функционал: **реализован**;
- независимость от расстояния: **реализована**;
- фильтрация по команде: **реализована и проверяется на сервере**;
- совместимость сборки с GTNH 2.9.0-beta-3: **подтверждена сборкой**;
- визуальное соответствие цели: **частичное**;
- подтверждённая работа в реальном мультиплеере: **ещё не проверена**.

## Что именно является целевой реализацией

Проверка проводилась не по общему описанию, а по тем же версиям модов, которые использует GT Community Pack Modern v1.14.1:

- Xaero's Minimap 25.2.6 для Forge 1.20.1;
- Xaero's World Map 1.39.9 для Forge 1.20.1;
- FTB Teams 2001.3.1.

Сверены серверные классы синхронизации и клиентские рендереры Tracked Players из этих JAR. Современный Xaero официально поддерживает FTB Teams и для дальних игроков требует серверную установку, потому что FTB Teams сам координаты игроков не синхронизирует.

## Визуальное сравнение

### Миникарта

Цель рисует голову примерно 10×10 px, использует обычный entity radar для загруженного игрока внутри рамки и отдельный tracked marker для удалённого/вышедшего за рамку игрока. Маркер закрепляется на реальной границе круглой или квадратной карты.

0.2.2 близка к цели на круглой миникарте: размер головы совпадает, есть передача управления обычному радару и clamp к краю. На квадратной карте найден определённый дефект: расчёт границы остаётся круговым. В углах маркер будет сдвинут внутрь, а для живого игрока возможны две головы — native radar в углу и наш marker на воображаемой окружности.

### Полноэкранная карта

Цель использует голову около 30×30 px. Имя скрыто и плавно появляется при наведении. Если игрок уже отрисован обычным радаром карты, дополнительный tracked marker подавляется, кроме состояния hover.

0.2.2 всегда рисует собственную голову 12×12 px и, по умолчанию, постоянное имя под ней. Функционально игрок виден, но внешний вид заметно отличается. При включённом радаре на большой карте остаётся риск двойного маркера для локально загруженного игрока — это надо подтвердить реальным тестом Xaero 1.14.1.33.

### POV

Цель:

- не рисует marker ближе 10 блоков;
- между 10 и 20 блоками плавно повышает прозрачность;
- дальше использует alpha 0.5;
- показывает имя только когда marker выделен прицелом;
- не рисует marker позади камеры.

0.2.2:

- по умолчанию разрешает marker с нулевой дистанции;
- использует постоянную alpha 0.45;
- всегда показывает имя;
- фиксирует далёкий marker на луче в 8 блоках от камеры;
- рисует через блоки и уважает F1/Hide GUI.

То есть назначение и читаемость сохранены, но близкая зона, fade и подпись не совпадают с целью.

## Проверки сборки и артефакта

Подтверждено ранее выполненным полным прогоном GTNH Gradle:

- `spotlessApply clean build` завершился успешно;
- `spotlessCheck check` завершился успешно;
- Checkstyle: 0 ошибок;
- reobfuscation выполнен;
- классы имеют bytecode Java 8 (`major 52`);
- JAR не содержит встроенных классов зависимостей;
- сборка выполнялась против Navigator 1.1.9 и ServerUtilities 2.4.9 из GTNH 2.9.0-beta-3;
- dedicated-server runner дошёл до стандартного запроса принятия Minecraft EULA; соглашение автоматически не принималось.

Официальная GTNH 2.9.0-beta-3 содержит Navigator и ServerUtilities, но использует JourneyMap. Для проверки именно заявленного сценария Xaero на клиент и сервер надо отдельно поставить совместимые версии Xaero's Minimap 21.10.44 и Xaero's World Map 1.14.1.33.

## Риски

1. **Определённый визуальный баг:** круговой clamp на квадратной миникарте.
2. **Высокая вероятность несоответствия UX:** слишком маленькая голова и постоянное имя на большой карте.
3. **Высокая вероятность несоответствия UX:** POV-marker виден слишком близко и всегда подписан.
4. **Требует проверки:** возможный дубль головы на fullscreen map при активном native entity radar.
5. **Требует проверки:** GL-состояние с OptiFine/шейдерами и другими HUD-модами.
6. **Требует проверки:** переход live entity → remote snapshot на границе client tracking range.

## Рекомендуемый порядок доработки

### P0 — до следующего тестового JAR

1. Хранить форму миникарты, переданную Navigator: круг для трёхаргументного `recacheMiniMap`, квадрат для четырёхаргументного.
2. Для квадратной карты делать ray-to-rectangle clamp, для круглой — радиальный clamp.

### P1 — для визуального соответствия GCP Modern

1. Fullscreen map: увеличить tracked head примерно до 30 px.
2. Fullscreen map: скрыть постоянное имя и показывать его по hover, если API Navigator позволяет; иначе сделать отключённым по умолчанию.
3. POV: `minDistance=10`, alpha 0→0.5 на дистанции 10–20, затем 0.5.
4. POV: показывать имя только при наведении прицела; если hit-test слишком дорог для 1.7.10, отключить постоянное имя по умолчанию.
5. Рассмотреть интервал 5 тиков (250 мс) для совпадения с целью; интерполяцию оставить как осознанное улучшение либо сделать отдельной опцией.

### P2 — полная функциональная паритетность

1. Поддержка просмотра tracked player в выбранной dimension полноэкранной карты.
2. Интерактивное имя/координаты и контекстное меню на карте, если это возможно через Navigator 1.1.9.
3. Явно решить, нужны ли ServerUtilities allies; текущее ограничение «только одна команда» соответствует заданию.

## Обязательная матрица реального теста

Нужны dedicated server и два клиента:

1. одна команда, 5–20 блоков;
2. одна команда, 200+ блоков за vanilla tracking range;
3. 5 000+ блоков;
4. телепорт `/home` или аналог на 128+ блоков;
5. переход между dimensions;
6. выход из команды и повторное вступление;
7. logout/login второго игрока;
8. круглая и квадратная миникарта;
9. fullscreen map при включённом и выключенном entity radar;
10. POV через стену, с F1, inventory и OptiFine/shaders;
11. отдельное выключение map и POV горячими клавишами;
12. перезапуск клиента с проверкой сохранения настроек.

До прохождения этой матрицы корректная маркировка релиза: **functional beta, multiplayer visual verification required**.
